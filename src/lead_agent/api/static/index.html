Lead Prospecting Agent
Consola Leads Arquitectura API · Swagger
Reto técnico · Prospección comercial automatizada

Del sector y la ciudad a leads verificados contra su fuente.

Un agente IA decide qué buscar, qué resultado es un lead real y qué datos extraer. Cada email, teléfono y dirección se comprueba en código contra la página citada antes de guardarse: lo que no aparece en la fuente, no entra a la base de datos.

  1. 01 · search_webBuscarConsultas por sector, distrito y nicho en fuentes públicas.
  2. 02 · LLMCualificarDescarta directorios, noticias, empleos y otras ciudades.
  3. 03 · groundingVerificarCada dato debe aparecer literalmente en la fuente citada.
  4. 04 · save_leadGuardarJSON validado, deduplicado y auditado en la base de datos.

    Cómo resuelve el reto

    Diseño agéntico

    El LLM decide cuándo buscar, guardar y terminar

    Tool calling nativo en un bucle ReAct con límites de pasos y búsquedas, y guardia de progreso ante bucles.

    agent/runner.py · agent/tools.py
    Prompt + código

    Cero datos inventados en la base

    Prompt de mundo cerrado con contraejemplos; JSON Schema desde Pydantic; verificación literal contra la fuente.

    agent/prompts.py · agent/grounding.py
    Arquitectura

    Capas y puertos intercambiables

    CLI, API y Lambda usan el mismo servicio. Cambiar LLM, buscador o base de datos es una variable de entorno.

    services/ · container.py
    AWS

    Serverless asíncrono y escalable

    API Gateway → Lambda → SQS → worker con Bedrock → DynamoDB, con DLQ, alarmas y plantilla SAM.

    infra/template.yaml
    Base de datos de leads

    Leads verificados

    Cada registro proviene de una ejecución auditada del agente. Nombre, contacto y web se comprobaron contra la URL de la fuente antes de guardarse.
